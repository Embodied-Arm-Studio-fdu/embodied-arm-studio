# 部署说明

首次安装优先按[快速开始](quickstart.md)运行启动引导。本文供需要 GPU、远程访问或日常维护的部署者查阅。所有项目命令都在部署机器的项目根目录执行。

## 模式与环境要求

| 项目 | Core | GPU |
| --- | --- | --- |
| 功能 | 课程、教材、账号、项目编辑和助手配置 | Core 功能，以及真实仿真、PPO 训练、实验视频和训练制品 |
| 宿主环境 | 推荐 Linux amd64；Python 3.8+、Docker Engine、Compose v2.20+ | Linux x86_64 NVIDIA 主机，另需兼容 CUDA 12.1 的驱动和 NVIDIA Container Toolkit |
| 私有镜像读取权 | API、Web | API、Web、Simulation、Worker |
| 外部资源 | 无需仿真 SDK | Isaac Gym Preview 4 SDK、完整 S1 description/URDF 和引用网格 |

宿主机无需安装本项目的 Python 依赖或 Node/npm。GPU Worker 的容器环境为 Ubuntu 20.04、Python 3.8、CUDA 12.1 和 PyTorch 2.4.1；现有参考硬件为 RTX 4080 16 GiB。准备足够磁盘存放 GB 级镜像、下载临时文件、数据库和持续增长的录像与制品。

部署机器需要访问 GHCR 及其镜像层端点，以及 Docker Hub 或团队配置的镜像源。启动引导默认使用 `deploy/images.json` 中的固定 digest，不在本机构建；再次启动仍会尝试拉取镜像，因此也需要网络和有效的 Docker 认证。权限与认证步骤见快速开始。

### 功能与平台范围

当前仿真目录实现了 Push、Reach、Grasp、Lift、Lower/Release、Place 和六种固定控制演示；网页能否启动还取决于课程项目、权限及目录状态。已有 Push 固定场景训练与回放结果，不能据此保证其他任务、跨场景或跨训练种子的效果。浏览器直播在目标环境仍需确认可播放，现有录像结果不代表所有远程网络均兼容。

Windows、macOS、WSL2 和 ARM64 宿主安装尚无完整验证。真实机器人控制未开放，界面标为规划中或不可用的能力仍不可使用。Isaac Gym SDK、完整机器人资源需自行合法取得；镜像与源码包不包含历史实验数据库、录像或已训练的 Push 策略。依赖与分发条款见 [NOTICE](../NOTICE.md)。

## 安装 GPU 模式

先准备驱动和 Docker GPU 访问，以及以下部署机上的绝对目录：

- Isaac Gym Preview 4 根目录，其中含 `python/isaacgym/_bindings/linux-x86_64/gym_38.so`。当前使用的不是 Isaac Sim 或 Isaac Lab。
- 完整 `yhrg_s1_description` 根目录，其中含 `urdf/yhrg_s1_v2.urdf` 和全部引用网格。网页预览用的资源子集不足以用于仿真。

部署文件内的三份参考初始化权重由脚本检查并准备，无需复制他人的训练输出。启动工具不会安装驱动、Toolkit、SDK 或修改防火墙；缺少条件时先由部署者补齐。共享 GPU 上先协调使用时间，并确认现有任务已结束，避免同时启动多个重型 Worker。

已完成快速开始中的源码获取与 GHCR 认证后，运行：

```bash
python3 scripts/start.py --config .env.team-gpu
```

选择 `gpu`。如需保留独立 Core 安装，使用不同安装名，例如 `team-gpu`、网页端口 `8081`，并填写自己的 SDK 和模型路径。独立安装使用各自的数据卷和账号，不自动迁移 Core 的数据；不要让两份配置同时管理同一个安装名。

本机浏览器或 SSH 回环访问时，监听地址和浏览器主机都填 `127.0.0.1`，**“通过 SSH 回环转发访问？”选择 `yes`**。该选项也用于同机浏览器，启用 localhost/TCP 视频模式。媒体 HTTP、ICE UDP、ICE TCP 默认端口分别为 `18889`、`18189`、`18191`，应全部未被其他安装占用。

局域网访问时，监听填 `0.0.0.0`，浏览器主机填服务器可达的 IPv4 或主机名，回环访问选 `no`。浏览器主机不带协议和端口；`0.0.0.0` 仅是监听地址。

引导检查环境、启动服务并设置账号。Worker 启动时检查 CUDA、PhysX、NVENC、Vulkan 和 Camera；检查失败时查看日志处理具体依赖问题。安装完成后，按[使用指南](user-guide.md)配置实验。

## 远程访问

以下示例用于采用上述默认设置的独立安装。已有团队平台使用维护人提供的网址和端口，不照搬新装示例。

### SSH 回环访问

在浏览器所在电脑运行并保持连接，替换自己的 SSH 登录名和服务器地址：

```bash
# Core：仅转发网页
ssh -N -L 8080:127.0.0.1:8080 YOUR_SSH_USER@YOUR_SERVER

# GPU：网页8081、媒体HTTP18889、ICE TCP18191
ssh -N -L 8081:127.0.0.1:8081 -L 18889:127.0.0.1:18889 -L 18191:127.0.0.1:18191 YOUR_SSH_USER@YOUR_SERVER
```

分别打开 `http://127.0.0.1:8080` 或 `http://127.0.0.1:8081`。GPU 需在安装时启用回环访问。SSH 视频模式使用 TCP；仅转发网页端口可以登录和读取录像，但不足以承载实时视频。

保持浏览器地址与配置中的 `STUDIO_WEB_ORIGIN` 一致。更改端口时，同时核对网页地址、媒体配置和隧道映射，避免工具自动改号后仍使用原地址。

### 局域网与公网

局域网访问需放通实际配置的网页 TCP 端口及媒体 ICE UDP/TCP 端口；媒体 HTTP 端口按连接方式配置。直播使用 WebRTC，不会自动回退为 HLS。

默认 HTTP 配置适合可信局域网或 SSH 隧道。公网部署需另行配置 HTTPS、媒体访问源、NAT/TURN 和防火墙；当前引导不自动配置这些设施。数据库、Redis 和内部回调接口无需对外开放。

## 日常启停

始终复用安装时的配置。以下为 Core 示例；GPU 安装替换为 `.env.team-gpu`：

```bash
# 启动或再次使用
python3 scripts/start.py --config .env.team-core

# 查看状态
python3 scripts/self_host.py --config .env.team-core status

# 查看最近100行并持续跟随日志
python3 scripts/self_host.py --config .env.team-core logs

# 停止服务，保留数据卷
python3 scripts/self_host.py --config .env.team-core down
```

查看日志时按 Ctrl-C 只退出日志查看。停止 GPU 服务前，先在平台结束运行中的实验并等待任务退出。`down` 会停止整套对应安装，不用于取消单个实验；取消实验请使用 Run 页停止操作。

`.env.team-core` 或 `.env.team-gpu` 保存安装名、端口、镜像引用和私有凭据，生成权限为 0600。保管好原文件，不删除数据卷，也不为已有数据库重新生成凭据。

## 备份、更新与恢复

维护前先结束活动实验，安排维护窗口。配套备份私有配置、PostgreSQL 数据库以及 API 的 `/app/var` 数据卷；数据库中的制品记录与实际文件应来自同一备份时间点。恢复时一并恢复，建议先在独立安装名、卷和端口下检查。

更新部署文件不会自动改写旧配置的镜像引用。维护人应依据新版本 `deploy/images.json` 核对需要更新的角色，在原配置中更新相应 `STUDIO_IMAGE_*` 固定引用，保留密码、路径、安装名与旧版本引用用于回退。完成备份和版本兼容性检查后，再使用原配置启动。启动流程会先执行数据库迁移，再等待服务就绪。

不要用重新安装替代数据恢复。已有团队平台可能使用专门的维护脚本，其启停和备份方式应以该部署的维护资料为准。

## 教学助手配置

内置基础助手不需要外部模型密钥。需要外部服务时，维护人可在私有配置中设置 `OPENAI_*`、`DEEPSEEK_*` 或 `ANTHROPIC_*` 对应环境值，再使用原配置启动服务。值保持单引号包围，避免 `$` 被展开。

网页配置的临时 Provider 只在当前 API 进程内有效，重启后需重新配置。模型密钥不写入网页构建变量、源码或问题报告；也不要用 GitHub 令牌代替模型服务密钥。

## 常见问题

| 问题 | 处理方式 |
| --- | --- |
| Docker 不可用或无访问权限 | 检查 Docker 服务、Compose 版本和当前用户权限，由部署者处理宿主环境 |
| 镜像拉取 401/403 | 在部署机器重新确认 Docker GHCR 认证、账号的包读取权及组织 SSO；能访问仓库不代表能读所有镜像 |
| 下载超时或磁盘不足 | 检查部署机器到镜像源的网络和磁盘余量，修复后复用相同启动命令 |
| 安装名或端口被占用 | 新安装选择未使用的名称和端口；已有安装找回原配置 |
| 登录失败或课程不可见 | 核对平台账号、当前密码、入口和教学班；联系维护人，不反复初始化账号 |
| Run 一直排队 | 查看对应 Worker 状态、队列配置和依赖检查日志，无需重复提交 |
| SDK 导入失败 | 确认挂载的是 Preview 4 根目录，包含 Linux x86_64 Python 3.8 绑定 |
| 缺少机器人网格或参考权重 | 核对完整模型目录、参考模型清单和只读挂载，不用任意权重替换 |
| 直播无画面 | 检查同一 Run 是否执行中、GPU 视频检查、网页 Origin、媒体地址和 ICE 端口；SSH 访问需转发 ICE TCP |
| 录像或下载失败 | 确认有效登录、Run 权限及制品是否已生成；向维护人提供 Run 链接与去敏错误 |
| 重启后助手 Provider 消失 | 临时配置随 API 进程结束；长期使用需配置服务端环境值 |
